## Purpose

This plan turns the accepted onboarding spec into small documentation batches. It prevents directory-first file spray.

## Batch Cadence And Split Gate

Deep Onboarding has no total document count cap. Write as many deep-dive docs as current project evidence and newcomer handoff needs require.

Default batch size is 1-3 deep-dive docs, unless the human chooses another review cadence. Batch size is review pacing, not a total limit.

Every proposed new onboarding file must pass this gate before writing:

| Proposed File | Batch | Why New File? | Why Not Merge? | Required-Core? | Human Value | Accept / Defer |
|---|---|---|---|---|---|---|

If the agent cannot explain why a new file must exist, merge the information into README, maps, coverage, or an existing deep-dive doc.

## Stop Conditions

Stop and ask the human before:

- writing outside the accepted onboarding spec / plan
- adding a new required-core onboarding topic without updating the plan
- creating directory-first module/flow/detail files
- marking any required-core topic `newcomer-ready`
- replacing source evidence with guessed business meaning
